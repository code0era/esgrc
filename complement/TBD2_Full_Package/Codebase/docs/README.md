# Documentation map

The documentation is grouped by purpose so that current operating material,
historical source material, and generated reference reports do not become mixed.

- `architecture/`: system flow, component contracts, and module interfaces.
- `analytics/`: analytics behavior, validation results, and module replication.
- `deployment/`: local, demo, and production setup and hosting guidance.
- `project/`: current state, readiness, decisions, handoffs, and planning.
- `team/`: role-specific handoffs and communication drafts.
- `strategy/`: product and funding strategy.
- `daily_reports/`: dated work reports.
- `reference/`: reports, data references, and retained implementation history.
- `source_documents/`: original project documents and their readable conversions.

Start with `architecture/HOW_IT_WORKS.md` for the product flow and
`project/PROJECT_STATE.md` for the latest documented project state.
