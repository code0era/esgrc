# Shared module analytics scripts

Source: Repo-01 commit [`75e6c86`](https://github.com/AI-ERMT-TBD-02/Repo-01/commit/75e6c86)
(Praveen, 3 Aug 2026). 11 Shared files were uploaded; the 5 `.py` are vendored here,
the 2 true inputs are in `modules/shared/reference_data/`.

The other 4 CSVs in that upload (`module_values_`, `filtered_metrics_`,
`filtered_groups_`, `filtered_sub_modules_`) are **derived outputs**, not inputs -
the pipeline regenerates them, so they are deliberately not vendored. A sixth
script, `AI_ready_Correlation_Analysis_Shared_5_0.py`, was uploaded and then
deleted in the same commit range; it is superseded by the `8_0` file below.

## Provenance: generated from our Customer copies, not from Praveen's Shared files

Praveen's `*_Shared_*` scripts differ from his `*_Customer_*` scripts **only** in
module tokens plus a few regressions (listed under "Deltas" below). Our
`modules/customer/analytics_scripts/` copies already carry every fix this module needs, so
these files were generated by retokenising **ours** (`customer`→`shared`,
`CUST_001`→`SHRD_001`) rather than by re-fixing his. Each generated file was then
diffed back against his upload to confirm the only differences are the intended
fixes.

Keep this set, `modules/customer/analytics_scripts/` and `modules/esgrc/analytics_scripts/` in sync.

## Deltas applied to Praveen's upload

1. **`app.run(debug=True)` disabled** in the LowPerf, Correlation and Regression
   scripts. The Flask dev server never exits, so a batch/subprocess run hangs
   forever. All outputs are written before that line, so disabling it is safe.
2. **SPC script: RPN summary TXT restored.** As with Customer, his
   `x_bar_r_chart_fmea_shared_5_0.py` has no `save_rpn_summary_txt` at all, so
   spec report #7 (the RPN table that feeds Claude in step 6/7) would not exist -
   only the stakeholder PDF. Ported `RPN_SUMMARY_COLS` + `save_rpn_summary_txt`
   and renamed the outputs to the `metrics_summary_` / `rpn_summary_` / `*_report_`
   convention the registry globs.
3. **Correlation script: report-size trim.** Shared has **288 metrics vs ESGRC's
   84**, and both the correlation dump and the inconsistency table scale with the
   *square* of the metric count. His version writes the full pairwise dump, which
   is what produced Customer's 9.1 MB step-6 payload. Ours writes top-150 pairs by
   `|r|` and top-30 inconsistencies by severity instead. The full matrices are
   still **computed** unchanged and still drive CHAID risk binning; only what is
   written to the LLM-facing report changed.
4. **Correlation script: output filenames suffixed.** His Shared version writes
   `trends_and_repetitions_report.txt`, `inconsistencies_report.txt` and
   `chaid_risk_segmentation_report.txt` with **no module suffix** (his Customer
   version suffixes all three). Unsuffixed names collide with other modules in a
   shared working directory and break the registry's `output_files` contract, so
   all three carry `_shared` here.
5. **Regression script: Windows UTF-8 stdout guard** (`sys.stdout.reconfigure`)
   added, matching ESGRC and Customer. Without it the emoji prints crash on
   cp1252 consoles.
6. **Regression script: duplicate top-level read dropped.** His Shared version
   reads `module_values_shared.csv` twice at module scope (his Customer version
   reads it once). Redundant, so the second read is not carried over.
7. **LowPerf: duplicated fallback loop body dropped.** His Shared version appends
   each metric's weight and value **twice** inside the no-groups fallback. It is
   numerically a no-op (the weighted average doubles both sums), and the path
   never fires for this module anyway - all 288 metrics sit inside groups - but
   ours keeps the single, correct body.
