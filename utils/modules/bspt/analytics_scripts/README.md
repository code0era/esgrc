# Business Partner (BSPT) module analytics scripts

Source: Repo-01 commit [`75e6c86`](https://github.com/AI-ERMT-TBD-02/Repo-01/commit/75e6c86)
(Praveen, 3 Aug 2026). 11 BSPT files were uploaded; the 5 `.py` are vendored here,
the 2 true inputs are in `modules/bspt/reference_data/`.

`bspt` is the routing/file token everywhere (it is what Praveen's scripts and data
files use); **Business Partner** is the display name. The other 4 CSVs in that
upload (`module_values_`, `filtered_metrics_`, `filtered_groups_`,
`filtered_sub_modules_`) are **derived outputs**, not inputs - the pipeline
regenerates them, so they are deliberately not vendored.

## Provenance: generated from our Customer copies, not from Praveen's BSPT files

Praveen's `*_BSPT_*` scripts differ from his `*_Customer_*` scripts **only** in
module tokens plus the regressions listed under "Deltas" below. Our
`modules/customer/analytics_scripts/` copies already carry every fix this module needs, so
these files were generated by retokenising **ours** (`customer`→`bspt`,
`CUST_001`→`BSPT_001`) rather than by re-fixing his. Each generated file was then
diffed back against his upload to confirm the only differences are the intended
fixes.

Keep this set, `modules/customer/analytics_scripts/` and `modules/esgrc/analytics_scripts/` in sync.

## Deltas applied to Praveen's upload

1. **`app.run(debug=True)` disabled** in the LowPerf, Correlation and Regression
   scripts. The Flask dev server never exits, so a batch/subprocess run hangs
   forever. All outputs are written before that line, so disabling it is safe.
2. **SPC script: RPN summary TXT restored.** As with Customer and Shared, his
   `x_bar_r_chart_fmea_bspt_5_0.py` has no `save_rpn_summary_txt` at all, so spec
   report #7 (the RPN table that feeds Claude in step 6/7) would not exist - only
   the stakeholder PDF. Ported `RPN_SUMMARY_COLS` + `save_rpn_summary_txt` and
   renamed the outputs to the `metrics_summary_` / `rpn_summary_` / `*_report_`
   convention the registry globs.
3. **Correlation script: report-size trim.** Business Partner has **336 metrics vs
   ESGRC's 84**, and both the correlation dump and the inconsistency table scale
   with the *square* of the metric count. His version writes the full pairwise
   dump, which is what produced Customer's 9.1 MB step-6 payload. Ours writes
   top-150 pairs by `|r|` and top-30 inconsistencies by severity instead. The full
   matrices are still **computed** unchanged and still drive CHAID risk binning;
   only what is written to the LLM-facing report changed.
4. **LowPerf: brought to 3_0 parity.** His BSPT LowPerf is `2_0`, branched from an
   older base than the Customer/Shared `3_0`, and is missing the
   `'value' in sub_module` guard on the no-groups fallback path. Ported. The
   filename keeps his `2_0` so provenance back to Repo-01 stays obvious; the file
   header records the discrepancy.
5. **Regression script: Windows UTF-8 stdout guard** (`sys.stdout.reconfigure`)
   added, matching ESGRC and Customer. Without it the emoji prints crash on
   cp1252 consoles.
6. **Regression script: duplicate top-level read dropped.** His BSPT version reads
   `module_values_bspt.csv` twice at module scope (his Customer version reads it
   once). Redundant, so the second read is not carried over.
7. **Regression script: output renamed** from `Business_Partner_Module_model_summary.txt`
   to **`BSPT_Module_model_summary.txt`**, matching the `{TOKEN}_Module_model_summary.txt`
   convention ESGRC and Customer use and keeping the registry uniform. Nothing
   downstream keys on this name - step 6 globs every `.txt` from steps 1, 3, 4, 5,
   and Apex reads only `data_for_risk_assessment_bspt.csv`. The human-readable
   report text still says "Business Partner".
